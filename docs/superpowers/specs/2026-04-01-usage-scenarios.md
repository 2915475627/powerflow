# PowerFlow 使用场景测试文档

## 概述

本文档设计内部测试场景，用于验证功能完整性和发现bug/痛点。

---

## 场景1：工作流管理

### 1.1 创建工作流
**步骤：**
1. 进入「工作流」页面
2. 点击「新建工作流」按钮
3. 输入工作流名称（如：测试工作流）
4. 观察是否出现重复名称检测提示（如已有同名工作流）

**验证点：**
- [ ] 能否成功创建新工作流
- [ ] 重复名称是否有友好提示
- [ ] 创建后是否正确跳转

### 1.2 编辑工作流
**步骤：**
1. 在工作流列表点击某个工作流的「编辑」按钮
2. 进入编辑器后修改工作流名称
3. 添加一个新节点（如HTTP请求节点）
4. 保存工作流
5. 再次编辑该工作流，检查修改是否保留

**验证点：**
- [ ] 修改是否正确保存
- [ ] 节点配置是否完整保存
- [ ] 重新编辑时数据是否正确加载

### 1.3 删除工作流
**步骤：**
1. 在工作流列表点击某个工作流的「删除」按钮
2. 确认删除操作
3. 检查工作流是否从列表中消失

**验证点：**
- [ ] 删除是否有确认提示
- [ ] 删除后列表是否正确更新

## 场景2：节点配置管理

### 2.1 创建LLM模板
**步骤：**
1. 进入「节点配置」页面
2. 展开「LLM调用」分组
3. 点击「+ 新建模板」
4. 填写表单：
   - 名称：我的GPT4配置
   - 供应商：OpenAI
   - 请求地址：https://api.openai.com/v1
   - 模型：gpt-4
   - API Key：sk-xxx（测试用假key）
   - Temperature：0.7
   - Max Tokens：2000
   - 备注：测试用
   - 官网链接：https://platform.openai.com
5. 点击保存

**验证点：**
- [ ] 模板是否出现在列表中
- [ ] 保存后表单是否关闭
- [ ] 列表是否自动刷新显示新模板

### 2.2 编辑LLM模板
**步骤：**
1. 在LLM模板列表中点击某个模板的「编辑」
2. 修改名称或参数
3. 点击保存

**验证点：**
- [ ] 编辑后内容是否正确更新
- [ ] 列表显示是否同步

### 2.3 删除LLM模板
**步骤：**
1. 在LLM模板列表中点击某个模板的「删除」
2. 确认删除

**验证点：**
- [ ] 删除后模板是否从列表消失
- [ ] 是否无需刷新页面

### 2.4 创建HTTP模板
**步骤：**
1. 展开「HTTP请求」分组
2. 点击「+ 新建模板」
3. 填写表单：
   - 名称：天气API
   - Method：GET
   - URL：https://api.weather.com/v1
   - 超时：30000
   - 备注：获取天气数据
4. 保存

**验证点：**
- [ ] HTTP模板创建是否成功
- [ ] 不同HTTP方法是否可选

## 场景3：工作流编辑器

### 3.1 添加和连接节点
**步骤：**
1. 进入编辑器（新建或编辑工作流）
2. 在右侧面板点击一种节点类型按钮（如「+ HTTP」）
3. 观察节点是否出现在画布上
4. 拖拽节点到目标位置
5. 从一个节点的输出句柄拖拽到另一个节点的输入句柄
6. 建立连接

**验证点：**
- [ ] 节点类型按钮是否都可用
- [ ] 节点添加后是否出现在画布
- [ ] 拖拽连接是否流畅
- [ ] 连接线是否正确显示

### 3.2 配置LLM节点
**步骤：**
1. 在画布上添加一个LLM调用节点
2. 点击该节点选中
3. 在右侧面板查看配置表单
4. 点击「加载配置模板」按钮
5. 在弹窗中选择一个LLM模板
6. 观察配置是否自动填充

**验证点：**
- [ ] 选中节点后右侧面板是否显示配置
- [ ] 「加载配置模板」按钮是否有效
- [ ] 弹窗是否正确显示可用模板
- [ ] 选择模板后配置是否正确填充
- [ ] 手动修改配置后是否生效

### 3.3 配置HTTP节点
**步骤：**
1. 添加一个HTTP请求节点
2. 选中后点击「加载配置模板」
3. 选择一个HTTP模板
4. 验证URL、Method等是否填充

**验证点：**
- [ ] HTTP模板是否正确填充
- [ ] 填充后能否手动修改

### 3.4 保存工作流
**步骤：**
1. 配置好工作流后点击「保存」按钮
2. 观察保存结果

**验证点：**
- [ ] 保存是否成功
- [ ] 是否有错误提示
- [ ] 保存后是否跳转到工作流列表

### 3.5 执行测试（单个节点）
**步骤：**
1. 在编辑器中添加并配置一个节点
2. 保存工作流
3. 在「执行测试」面板：
   - 确保已选择一个节点
   - 输入Context：`{"input": {"value": "test"}}`
   - 点击「执行测试」
4. 观察执行结果

**验证点：**
- [ ] 执行测试面板是否正常显示
- [ ] 节点ID是否正确
- [ ] 执行结果是否正确展示
- [ ] 成功/失败状态是否清晰

### 4.1 查看执行历史
**步骤：**
1. 进入「监控」页面
2. 查看执行历史列表

**验证点：**
- [ ] 历史列表是否正确显示
- [ ] 列表项信息是否完整（时间、状态、工作流名称）

### 4.2 查看执行详情
**步骤：**
1. 点击某个执行记录的「查看」按钮
2. 观察执行详情

**验证点：**
- [ ] 详情是否显示节点执行情况
- [ ] 各节点的输入输出是否可见
- [ ] 耗时、状态是否准确

## 场景5：完整工作流测试

### 5.1 创建包含多种节点的工作流
**步骤：**
1. 创建新工作流：「API数据处理流程」
2. 按顺序添加节点：
   - HTTP请求节点 → 获取数据
   - LLM节点 → 处理数据
   - 条件节点 → 判断结果
   - 数据处理节点 → 格式化输出
3. 连接所有节点
4. 为每个节点配置必要参数
5. 保存工作流

**验证点：**
- [ ] 所有节点类型是否都能添加
- [ ] 节点配置是否相互独立
- [ ] 连接是否建立正确的数据流

### 5.2 执行完整工作流
**步骤：**
1. 保存工作流后，在编辑器中点击「执行」
2. 观察整体执行过程
3. 进入监控查看执行结果

**验证点：**
- [ ] 执行是否按节点顺序进行
- [ ] 前置节点输出是否正确传递到后续节点
- [ ] 条件分支是否正确判断
- [ ] 执行失败时错误信息是否清晰

## 场景6：边界情况和异常

### 6.1 空工作流保存
**步骤：**
1. 创建新工作流
2. 不添加任何节点
3. 直接点击保存

**验证点：**
- [ ] 是否有提示不能保存空工作流
- [ ] 无节点时是否允许保存

### 6.2 节点未配置完整
**步骤：**
1. 添加一个LLM节点
2. 不配置任何参数
3. 保存工作流
4. 执行该节点

**验证点：**
- [ ] 保存是否成功（即使配置不完整）
- [ ] 执行时是否有参数缺失提示

### 6.3 删除正在使用的模板
**步骤：**
1. 创建一个使用某模板的工作流节点
2. 保存工作流
3. 进入「节点配置」删除该模板
4. 再次编辑该工作流

**验证点：**
- [ ] 删除模板后已使用该模板的节点如何处理
- [ ] 是否有相关提示或保护

### 6.4 网络错误模拟
**步骤：**
1. 配置一个HTTP节点指向不存在的URL
2. 执行该节点

**验证点：**
- [ ] 错误信息是否友好
- [ ] 是否显示具体错误原因
